NOT USED AT v0.1.

This file fixes the location and the shape of the §5.1 tier-2 prompt. It is not loaded by any
code path, and it is not listed in `manifest.toml`, because tier 2 depends on fetching the
registry's own subject and record-type lists — and no v0.1 registry route can fetch them.
Writing this prompt against a hard-coded list of subjects would breach R3.5 in the first commit,
which is exactly what §5.2 warns against.

When it is implemented, the constraint it must express is:

- The candidate terms are supplied in the prompt, fetched from the registry at query time.
- The model **picks from that list**. It does not write labels of its own.
- **Picking nothing is a permitted answer**, and a better one than a term that does not fit.
- Only the dataset's own description and derived column *metadata* appear here. Sample values
  never do (§1.4).
